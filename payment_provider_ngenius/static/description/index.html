Payment Flow

What happens from checkout to confirmation.

The integration stays close to the provider's hosted purchase flow and performs status verification on the way back into Odoo.

01
The customer selects N-Genius. The provider appears as an Odoo payment option for card payments.
02
Odoo creates a PURCHASE order. The request is sent to N-Genius with amount, currency, redirect URL, and available billing details.
03
The shopper pays on N-Genius. The hosted page handles the checkout experience outside the Odoo storefront.
04
Odoo verifies the order on return. When the customer comes back, Odoo fetches the latest order state from N-Genius before updating the transaction.
05
Webhooks confirm backend status. Purchase, capture, failure, cancellation, and refund notifications trigger another authoritative refresh.

Go-Live Notes

Operational details worth knowing before launch.

These points come directly from the implemented flow and the practical constraints of the N-Genius API.

Public base URL required

Odoo must use a public hostname. The module rejects localhost and loopback return URLs, and sandbox commonly refuses them as redirect targets.

Webhook endpoint

Configure /payment/ngenius/webhook in N-Genius and keep the endpoint on HTTPS with any required sandbox or production whitelisting completed.

Currency alignment matters

N-Genius can reject order creation when the transaction currency is not enabled on the configured outlet.

3DS behavior is strict

The implementation only accepts fully authenticated ECI values and treats attempted or incomplete 3-D Secure outcomes as failed payments.

Billing address is optional

Odoo sends billing details only when partner name, street, city, and country are all available.

Encrypted webhooks are out of scope

The module expects standard JSON webhooks. If encrypted webhooks are enabled in N-Genius, this module must be extended to decrypt them first.

FAQ

Common pre-sales and go-live questions.

These are the questions merchants usually ask before rollout, especially when they are validating domains, credentials, currencies, and refund expectations.

Does Odoo collect card details?

No. Customers are redirected to the hosted N-Genius payment page, so card data is entered on the provider side.

Can I test before going live?

Yes. Set the provider to test mode, configure sandbox credentials, and complete a full return plus webhook cycle before enabling production.

Does it support partial refunds?

No. The implemented refund flow supports full refunds only.

Why can a valid setup still fail?

Common causes are an invalid public callback hostname, outlet currency mismatch, or a webhook configuration that has not been whitelisted correctly in N-Genius.
